## 3.5 时间与时区

- 团队默认时区：`Asia/Shanghai`（UTC+08:00），由合同 `project.timezone` 声明。
- 数据库：按合同/ADR 使用数据库的带时区类型或显式存储偏移（例如 PostgreSQL `timestamptz`、SQL Server `datetimeoffset`）；不要用无时区的 `timestamp` 存业务时间。
- API/日志/事件/UI：ISO 8601 带偏移（例如 `2026-11-18T09:30:00+08:00`），不要只发 `YYYY-MM-DD HH:mm:ss`。
- 仅在存储层必须使用 UTC 时，读写边界和展示层必须转换为北京时间，并写 ADR；不能把 UTC 直接展示给用户。
- 测试固定时钟时明确时区；禁止依赖运行机器的本地时区。

## 4. 注释规范（强制）

- 代码注释必须中文；代码标识符、命令、字段名、错误码保持英文。
- 每个方法至少方法级注释：说明职责、输入/输出、副作用、失败语义。
- 复杂业务流程必须写行级或段落注释：状态转换、权限判定、事务边界、幂等/并发、回滚路径。
- 不写重复代码字面含义的注释；注释解释“为什么”，不是“是什么”。
- 修改行为时同步更新相关注释；过期注释视为缺陷。
- 历史代码注释迁移单独成任务，不和行为变更混合。

## 5. 测试与覆盖率

- 测试分层：单元、集成、E2E；关键旅程必须有独立验收。
- 覆盖率命令：`commands.coverage`（合同）。
- 门槛：line ≥ `constraints.coverage.line`，branch ≥ `constraints.coverage.branch`；已有项目不得低于基线。
- 排除项（生成代码、纯配置、迁移、DTO 等）必须逐项列出并说明理由；不得排除核心业务逻辑。
- 负例优先：401/403、边界、并发、失败恢复、输入校验。
- 报告与证据：覆盖率报告必须可由命令复现，并记录为 EV/CI artifact。
