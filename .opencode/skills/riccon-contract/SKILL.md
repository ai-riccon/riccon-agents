# Riccon 合同

项目合同是 `AGENTS.md` 中的一个受管 YAML 区块，位于 `<!-- riccon:contract:start -->` 和 `<!-- riccon:contract:end -->` 之间。它是团队关于技术栈、命令、工具、环境、约束和 DoD 的唯一事实源。

## 1. 读取

会话开始时：

1. 读 `AGENTS.md`。
2. 提取合同区块。
3. 运行 `riccon contract validate`。
4. 用仓库实际情况交叉检查路径和命令。
5. 路径或命令缺失时报告，不要猜。

## 2. 校验

`riccon contract validate` 检查：

- schema：必填字段、枚举、类型；
- 重复的工具/模块 ID；
- 风险等级对应的命令是否缺失；
- 产品目标/MVC/技术栈是否为空；
- repo-map 路径是否还不存在；
- DoD 默认值。

`--strict` 把 warnings 升级为 errors。发布前或接管现有项目时用 strict。

## 3. 起草与接管

现有项目的 `riccon adopt`（M3）只读检查：

- 语言、框架、包管理器、构建文件；
- 源码/测试根、文档根、契约、基础设施；
- 现有命令和 CI；
- 数据库、迁移和集成；
- 风险信号：认证、支付、PII、生产数据。

它提出带证据的合同草案。用户批准或修正后才写入。不要编造未检测到或未确认的版本、命令或依赖。

绿地项目的合同从大部分为空开始。Lead 问用户产品目标/用户/MVC/non-goals；Architect 提技术栈和命令；用户批准不可逆部分。

## 4. 冲突规则

- 合同优先于假设，但仓库优先于过期合同。两者不一致时停下来问。
- 失败的命令是合同 bug 或仓库 bug；记录证据，先解决再构建。
- 声明为 required 的工具缺失时是 blocker 或已批准的降级；绝不静默跳过。
- 缺失路径在需要它的模块开始前是 warning，之后是 blocker。
- 风险等级不确定时向上取，不向下取。

## 5. 变更流程

改技术栈、命令、工具或 DoD 是关键决策：

1. 写决策包：选项、后果、推荐。
2. 等用户答复；只有 T1–T3 可逆且写明默认值时才可沉默执行。
3. 准备合同区块的 diff。
4. 写入；编辑 `AGENTS.md` 需要审批。
5. 运行 `riccon contract validate`。
6. 在 ADR 或决策包里记录变更。
7. 更新 `.riccon/project.json` 的合同哈希。

产品范围变更走同样的决策包，但产品范围永远由用户拥有。

## 6. 合同里的工具

工具是声明的，不是假设的：

```yaml
tools:
  required:
    - id: example
      purpose: 这个项目为什么需要它
      fallback: 不可用时怎么办
  optional: []
  mcp: []
  fallback: 记录降级，改范围前先问用户
```

- 团队启动时检查可用性。
- required 缺失 → blocker 或已批准降级。
- optional 缺失 → 记录后继续。
- MCP 工具必须在 OpenCode 配置中启用；合同只声明意图和路由。
- 不要因为一个项目需要某工具就把它写进团队定义。团队保持与栈无关。

## 7. 合同质量标准

- 命令从项目根目录可直接复制运行。
- 路径真实存在，或明确标注为计划中。
- DoD 的 key 与 verifier 实际检查的一致。
- 决策所有者明确。
- 预算策略说明软/硬上限时发生什么。
- 合同里没有密钥、token 或私有 URL。
